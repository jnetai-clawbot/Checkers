# Checkers — Changes

## v1.3.0 (2026-08-30)

Instant human moves, a user-configurable AI reply delay, and a proper
end-of-match flow for online games (Rematch / Chat / Quit session).

### What changed
- **Player moves are now instant** — your own move (and every move your online
  opponent makes) lands on the board the moment it is made. The only artificial
  pause in the whole game is the AI's reply wait.
- **Settings → "AI reply delay"** (new): choose how long the AI "thinks" before
  it moves — **Instant (0s), 1s, 2s or 3s** (2s by default). After the chosen
  delay the AI still glides its piece slowly across the board so you can always
  see what changed. Instant = the AI replies immediately with no glide.
- **Online match end dialog** now offers three choices to both players:
  - **Rematch** — if both players tap Rematch a brand-new game starts instantly
    (no trip back to the menu). Each side is told when the opponent wants one.
  - **Chat** — swap messages with your opponent, with a **Rematch** button built
    right into the chat so you can agree to play again while chatting. Incoming
    messages appear as toasts when the chat window is closed.
  - **Quit session** — either player can leave; both players are returned to the
    Multiplayer screen where they can host / join / Quick Match again.
- `build.yml` now runs the JVM unit tests (`testDebugUnitTest`) before building
  the signed release APK.

### Files
- `GameActivity.kt`: instant human moves; AI delay reads the new setting
  (`applyAiMove` extracted); end-of-session rematch/chat/quit + P2P message
  handling (`REMATCH`, `CHAT|`, `QUIT_SESSION`); `sessionReturnToMultiplayer`
  flag so quitting can return to the pairing screen.
- `OnlineActivity.kt`: stays on the pairing screen after a "Quit session"
  instead of auto-finishing.
- `utils/SettingsManager.kt`: persistent `ai_think_seconds` (0-3, default 2).
- `settings/SettingsActivity.kt` + `activity_settings.xml` + `arrays.xml` +
  `strings.xml`: "AI reply delay" drop-down with Instant / 1 / 2 / 3 seconds.
- `strings.xml`: rematch / chat / quit-session copy.
- `net/PeerTransport.kt`: user agent bumped to `CheckersApp/1.3`.
- `app/build.gradle`: `versionCode 6`, `versionName 1.3.0`.

## v1.2.1 (2026-08-30)

Online multiplayer board-sync fix: both players must always see both their own
**and** the opponent's pieces, in every multiplayer mode / connection method.

### What was wrong
- In some live online matches only one player's board stayed correct; the other
  player saw only their own pieces. The old transport relayed a validated move
  (from/path/captured), and `onMovePlayed` re-broadcast inbound moves back to the
  sender; any rejected / echoed / re-ordered message left one side's engine one
  or more moves behind, so the opponent's pieces never moved on their screen.

### The fix (authoritative board-state sync)
- Online moves are now sent as a full, authoritative engine **STATE** snapshot
  (`STATE|<rules>|<moveCount>|<currentPlayer>|<noCapturePly>|<capturedBlack>|<capturedWhite>|<board>|<lastFrom>|<lastTo>`)
  instead of a single jump. The challenger **overwrites** its engine from the
  state, so its board always matches the host's exactly - both players always see
  every piece.
- Inbound states are de-duplicated by the monotonic `moveCount`, so stale echoes
  and duplicates are ignored harmlessly.
- Received moves are **no longer echoed** back to the sender.
- The challenger adopts the host's rule preset from the state (if the two devices
  have different settings) so the two boards are always the same size / layout.
- The host sends an initial state right when the match starts, so boards align
  from move one. New Game also re-syncs both sides.
- Legacy single-move payloads are still parsed as a defensive fallback.

### Files
- `GameActivity.kt`: `onStateReceived`, `serializeState`, relay flag on
  `onMovePlayed`, host initial-state push, preset adoption, no-echo receive path.
- Added `OnlineSyncTest.kt` (4 JVM tests): echo/clean/state protocols keep two
  peer engines perfectly synchronised across hundreds of moves, including when
  one peer starts on a different rule preset.

## v1.2.0 (2026-08-30)

Online multiplayer reworked so players can actually connect over the internet,
plus a more realistic AI opponent.

### Online multiplayer (P2P over the internet)
- **Root cause of E-NET-002-CONNECT fixed**: the old transport dialed the host's
  private LAN IP directly over TCP, which fails across NAT. The game now uses
  **WebRTC (PeerJS)** in a hidden WebView with public **Google STUN** servers and
  the **openrelay.metered.ca TURN** relay, so opponents connect through NATs over
  the public internet.
- Handshake / moves / resign / ping now flow over the WebRTC data channel
  (`HELLO` / `ROOM_OK` / `MOV` / `RESIGN` / `PING`), validated by the same engine.
- **Quick Match (random)** button added: first looks for an existing host (a
  rolling "lobby slot" PeerJS id), connects to it; if no host is found it
  auto-hosts a room and waits, **looping until a player is available**. Existing
  host-by-code / join-by-code / QR / share methods still work (and now work over
  the internet).
- Hosting and joining over internet; share code is now a short WebRTC id token
  (`CKRS:<id>`) still shown / copied / shared / QR-scanned.
- Share button shortened to **"Share"** and kept in line with the other pairing
  buttons.

### Realistic AI
- The AI now "thinks" for a couple of seconds (1.6–3s, randomised) before replying
  instead of moving instantly.
- The chosen piece glides **smoothly and slowly** to its destination (approx 650ms
  per hop) so you never miss what move was made; last-move highlight shows after.

### Files
- Added `net/PeerTransport.kt` (WebView + JS bridge), `Net/P2PManager.kt` rewritten
  as a facade over the bridge.
- Added `assets/web/bridge.html`, `assets/web/js/bridge.js`, `assets/web/js/peerjs.min.js`.
- `ui/CheckersBoardView.kt`: AI move glide animation.
- `GameActivity.kt`: thinking delay + animated AI move + transport lifecycle.
- `OnlineActivity.kt`: Quick Match / random cancel, transport init, status text.
- `activity_online.xml` / `strings.xml`: Quick Match button, "Share" label.
- `app/build.gradle`: version 1.2.0 (code 3), `androidx.webkit` dependency.

## v1.1.0 (2026-08-28)

Rules audit: the default **UK / Europe** preset now plays accurate **UK English
Draughts**.

### Rule fixes
- **Non-flying kings**: the UK preset previously used flying kings (kings could
  slide any distance when moving and capture across gaps). Kings now move and
  capture exactly one square, forwards and backwards.
- **Adjacent-capture only**: captures no longer jump across an empty gap. A man
  or non-flying king must have the enemy on the immediately adjacent diagonal
  square and an empty landing square beyond it.
- Captures remain **compulsory**; when a capture exists the only selectable and
  valid moves are captures.
- **No maximum-capture rule**: players may choose any legal capture path even if
  a longer chain exists (International "capture the maximum" remains a separate
  preset).
- **Multi-capture**: chain captures are applied atomically as one move so a piece
  stays locked in its capture sequence, the turn does not switch mid-chain, and
  truncated/partial chains are rejected by the engine.
- **Promotion ends the capture turn**: a man crowned on the back row during a
  capture stops immediately.
- **Men move/capture forward only**; kings move and capture forwards and
  backwards; kings never fly.
- Win conditions: zero pieces or no legal moves loses. Draws are not declared
  merely because no capture is available (only the 40-move rule style limits
  remain).

### UI (CheckersBoardView)
- Only pieces with a legal move are selectable.
- When a capture is compulsory the capturing pieces are ringed in red; movable
  (non-capturing) pieces get a subtle blue ring.
- A piece with no move cannot be selected, so a mandatory capture can never be
  ignored on the board.

### Tests
- Added `GameEngineTest` (31 JUnit cases) covering board setup, men, captures,
  multi-captures, kings, promotion, capture priority, win/draw, AI conformance
  and server-side (engine) move validation.

## v1.0.0 (2026-08-28)

Initial release. First fully working version (full dark-theme Checkers game).

### Features
- Three game modes:
  - **Play vs AI** — fully offline computer opponent
  - **2 Player** — pass & play on the same device, fully offline
  - **Online Multiplayer** — direct peer-to-peer matchmaking using a share
    code (copy / share sheet / QR code to scan), raw TCP transport.
- **Settings**
  - AI difficulty: Easy / Medium / Hard
  - Worldwide rules presets:
    - **UK / Europe (default)** — English draughts (8x8, men jump forward,
      non-flying kings, mandatory capture, no maximum-capture rule)
    - US / American — 8x8, kings move one square, mandatory capture
    - International — 10x10, men capture forward & backward, flying kings,
      majority capture
  - Per-player timer (off / 3 / 5 / 10 minutes)
  - Sound effects toggle
- **High Score board** (viewable from the main menu):
  - Recorded when you beat the AI; player can enter their name
  - Fewest moves = higher score; a faster time boosts the score when timed;
    time shown when a timer is used
  - Top 10 persisted locally (offline)
- **About section**
  - "Made by jnetai.com"
  - Full version number (matches GitHub release tag v1.0.0)
  - Check for update (GitHub API, with graceful fall-back to the release
    page if the check ever fails)
  - Share App button
- AI engine: negamax with alpha-beta pruning (depth 8 on Hard), offline only.
- Persistent error handling / logging: `ErrorLogger` (E-CODE-###), global
  uncaught-exception handler, logging kept permanently integrated in the code.
- Dark professional theme, centred layout, safe bottom spacing so controls are
  not cut off.
- Compatible with Samsung S8+ (minSdk 24) and Pixel 6+.

### Build / release
- Built and signed on GitHub Actions only (never locally).
- Pushed to its own repository: `jnetai-clawbot/Checkers`.
- Release triggers on tag push (`v*`), tagged `v1.0.0`.
- Uses its own dedicated keystore (`checkers-keystore.jks`) so future updates
  install over the top without uninstall. Keystore credentials in the local
  password vault and GitHub repo secrets.
- Final APK downloaded into `apk/` and `android/apk/`.
